## Запуск

```bash
cp .env.example .env        # впишите AI_API_KEY (необязательно) и SECRET_KEY
docker compose up --build   # http://localhost:8000
```

Без Docker: `pip install -r requirements.txt`, затем `uvicorn index:app --reload`.
База `snalma.db` создаётся и заполняется тестовыми данными при первом запуске.

## Тестовые аккаунты (пароль `demo123`)

| Логин | Роль | Что видит |
|---|---|---|
| `aigerim`, `erlan` | Сотрудник | только свои данные и заявки |
| `marat` | Руководитель | свои заявки и заявки своей команды |

## Сценарии

1. Вход, личный кабинет: профиль, остаток отпуска, быстрые сервисы, уведомления.
2. Заявка «Отпуск» или «Аванс»: руководитель → HR → одобрена/отклонена, история и уведомления на каждом шаге.
3. Руководитель видит только свою команду. Права проверяются на сервере: чужая заявка по прямой ссылке даёт 403.
4. Jana Academy: назначенный курс, материал, тест, прогресс и результат в профиле.
5. AI Jana: ответ по `data/knowledge.txt` с указанием источника.
6. Вопрос вне базы: «нет надёжной информации», предложение обратиться в HR. Вопросы о других сотрудниках блокируются.
7. RU/KZ-переключатель: переведены навигация и основные заголовки, остальное на русском.

## Архитектура

```
Браузер ── FastAPI (index.py) ── SQLite (db.py)
                │
                ├── ai/ai.py ── data/knowledge.txt ── (опционально LLM)
                └── integrations.py ── [1С:ЗУП: кадровые данные, read-only]
                                       [Documentolog: регистрация заявок]
```

Подключение реальных систем: заменить функции в `integrations.py` на клиенты 1С:ЗУП и Documentolog, интерфейс и маршруты остаются прежними.

## Безопасность

Секреты хранятся в `.env` (в git не попадает). Пароли в демо хешируются PBKDF2. Реальных персональных данных в репозитории нет.
База знаний демонстрационная: правила компании нужно заменить на актуальные.
